── 1/5  F-7  ·  following the data-modeling guide ──────────────────────────────────────────────
  Arkiv's guide says: project + entity_type scopes an application's data.
  Let's follow it exactly.

  query 1 — the documented discriminator, unscoped:
  $ entity_type = str('price_report')
    0  entity_type = str('price_report')   [cache]

  query 2 — the documented discriminator, scoped to the right project:
  $ project = str('mandi_board_v1') AND entity_type = str('price_report')
    0  project = str('mandi_board_v1') AND entity_type = str('price_report')   [cache]

  Both return 0 rows. Neither errors.
  This project has 97 entities and price reports are the majority of them.

  query 3 — same project, same data, the REAL discriminator:
  $ project = str('mandi_board_v1') AND type = str('price_report')
   63  project = str('mandi_board_v1') AND type = str('price_report')   [cache]

  63 rows.
  query 4 — the other type value in the same project:
  $ project = str('mandi_board_v1') AND type = str('price_vote')
   34  project = str('mandi_board_v1') AND type = str('price_vote')   [cache]

  63 + 34 = 97. The project was fully populated the whole time.
